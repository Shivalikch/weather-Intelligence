1Understanding the Requirement↑ Top

AFCENT (the air component of USCENTCOM) currently relies on disparate weather systems that hamper data fusion, accessibility, and operational tempo across an austere, high-stakes area of responsibility. The Performance Work Statement (PWS) seeks a fully-managed, commercially-hosted Weather Intelligence SaaS — accessed over NIPRNet via browser, delivering decision-quality METOC intelligence, with classified-enclave parity achieved by pushing data products through a Government Cross-Domain Solution (CDS). The five specific tasks below drive every design decision in this document.

PWS TaskWhat the Government requiresKey performance targets
Task 1
Global AI-Native Prediction		 Proprietary AI-native global atmospheric model with independent data assimilation (LEO passive-microwave sounders + geostationary + institutional NWP), producing a unified multi-sensor merged precipitation product and fully probabilistic forecasts. 25 km global / sub-10 km regional; global refresh ≤6 h, regional hourly; ≥60 data layers (core wx, clouds, WBGT, maritime, air quality, Land Information System, flood, aviation).
Task 2
Hi-Res Regional Model		 Convection-permitting hyper-local probabilistic ensemble over the CENTCOM AOR (Middle East, Arabian Peninsula, East Africa, South Asia). 3 km grid; 15-min output cadence; 36-h horizon.
Task 3
Decision Logic Engine		 Configurable rules engine letting planners define mission thresholds (rotary-wing wind limits, convoy visibility minimums, etc.); continuously evaluates forecasts and emits structured machine-readable alert objects. Custom thresholds by mission/platform/phase; alerts & insights delivered via authenticated API in JSON / GeoJSON.
Task 4
Severe-Weather Detection		 Continuous, operator-independent AOR-wide monitoring for environmental shaping events. Pre-built detections: blowing dust/sand, extreme heat/cold, heavy precip, thunderstorms & convective wind, hail, tornado, fog, significant sea state.
Task 5
Integration & Support		 Secure authenticated APIs (REST / GraphQL); unclassified-vs-classified product parity via Government CDS to SIPR/JWICS/C2; RMF/ATO-aligned artifacts; virtual onboarding & training. HTTPS/443; JSON & GeoJSON; 99.9% monthly uptime SLA; IOC in 14 days, regional FOC in 30 days.
Cross-cutting UX mandate. The live technical demonstration is scored on a map-centric, intuitive "no-code / low-code" interface that lets a non-technical planner set up a custom alert and generate a mission-specific forecast — and on how clearly the platform communicates model bias and operational impact to both expert forecasters and general operational planners.
Q&A relaxations (Amendment / Q&A #2). The strict FedRAMP hosting requirement was removed — a standard commercial cloud with industry-standard security is acceptable; the Government sponsors CDS/ATO ingestion (no pre-existing transferable DoD ATO required to bid); a phased IOC→FOC delivery is allowed; and the live demo is conducted virtually via Microsoft Teams.
Prototype thesis. We cannot reproduce a proprietary AI-NWP model or classified networks on a laptop — nor do we need to to win the demo. The prototype proves the decisive, scoreable capabilities: a map-centric no-code experience, a working threshold/rules engine that emits machine-readable GeoJSON alerts, severe-weather detection over the CENTCOM AOR, probabilistic display with plain-language operational-impact translation, and a mock "CDS export payload" that demonstrates the classified integration contract — all powered by free public weather data (Section 8).

2Three-Layer Architecture↑ Top

A classic three-tier separation — presentation (React + Vite), a middle API/logic layer (Python FastAPI), and persistence (SQLite) — chosen so the same shape scales cleanly to the AWS production design in Section 6. The scheduler pulls public data on the PWS refresh cadences; the rules engine turns forecasts into alert objects served as JSON/GeoJSON.

5Prototype Scope (Local, Zero-Cost)↑ Top

The prototype runs entirely on a laptop with free/open-source tooling and free public data. It demonstrates the scoreable demo capabilities end-to-end while transparently mocking anything that requires classified networks, GPUs, or proprietary models.

✓ In Scope — Built & Demonstrated

  • Map-centric workspace over the CENTCOM AOR with toggleable weather & satellite layers.
  • No-code alert builder — a wizard where a planner sets thresholds (e.g., surface wind > 25 kt, visibility < 3 mi, WBGT > 88°F) tied to mission presets.
  • Rules / threshold engine that continuously evaluates ingested forecasts and generates machine-readable GeoJSON alert objects.
  • Severe-weather detections — demo rules for blowing dust/sand, extreme heat, convective storms & fog across the AOR.
  • Probabilistic display — ensemble spread & likelihood, with plain-language operational-impact and model-bias cues for non-experts.
  • Authenticated REST API serving forecasts, rules & alerts as JSON/GeoJSON (OpenAPI docs live).
  • Mock CDS export — a payload inspector showing exactly what would be pushed to SIPR/JWICS, proving the integration contract.
  • Scheduler polling public sources on representative cadences; SQLite persistence of rules, AOIs & alert history.

✗ Out of Scope — Represented / Mocked

  • Proprietary AI-native global model with LEO passive-microwave assimilation — substituted with public NWP/AI-model outputs (GFS/GEFS, ECMWF AIFS).
  • True 3 km / 15-min convection-permitting ensemble — approximated with best-available public resolution; full fidelity needs GPU compute.
  • Full ≥60 data layers — a representative subset is wired; the layer framework is extensible.
  • Classified networks & live CDS (SIPR/JWICS) — represented by the mock export payload only.
  • Production authentication (CAC/PKI, SSO) — a simple token/login stands in.
  • ATO/RMF accreditation, 99.9% SLA, HA — design-only; not exercised locally.
  • Real-time global 6-h refresh at 25 km continuous operations — demo runs on-demand / scheduled samples.
Local run shape. Two processes: uvicorn app.main:app (FastAPI on :8000) and npm run dev (Vite on :5173, proxying /api). SQLite file created on first run; APScheduler seeds an initial data pull. A future step can wrap both in docker compose to mirror the ECS task definitions used in production.

6MVP Roadmap & Integration Path↑ Top

Rather than one monolithic build, the platform is decomposed into independently valuable MVPs — each a vertical slice mapping to one or more PWS tasks, delivered in a sequence that hits the 14-day IOC / 30-day FOC milestones and then matures toward full operational capability. Every MVP is loosely coupled through a shared JSON/GeoJSON contract, so later slices (higher-resolution models, the real AI engine, the classified gateway) plug in without reworking the UI or the earlier MVPs.

How the MVPs integrate over time

Loose coupling by design

  • Shared contract. Every MVP speaks one JSON/GeoJSON schema — forecast fields plus the alert objects defined in MVP-2 — so slices evolve independently.
  • Event-driven alerting. The rules engine emits events (EventBridge in production), decoupling detection (MVP-4) from delivery (MVP-6).
  • Pluggable adapters. MVP-5 (regional) and MVP-7 (real AI model) slot in behind the normalization layer; the map, panels, and rules engine are unaffected when fidelity improves.

Sequencing & the classified seam

  • IOC (≤14d): MVP-1 + MVP-2 deliver a working map, no-code alerting, and the GeoJSON API — the scoreable demo core.
  • FOC (≤30d): MVP-3 + MVP-4 add probabilistic/impact context and prebuilt AOR severe-weather detections.
  • Post-FOC / Production: MVP-5 raises resolution, MVP-7 introduces the real AI engine, and MVP-6 is the single outbound boundary where unclassified→classified parity is handled once, at the gateway.

8Limitations, Assumptions & Risks↑ Top

Stated plainly so stakeholders understand exactly what the prototype does and does not prove, and what must be true for it to demo successfully and to scale.

Limitations

  • Public data resolution/cadence is coarser than the PWS 3 km / 15-min and 25 km global targets.
  • No real assimilation of LEO passive-microwave sounders; precipitation is a public multi-sensor analog (GPM IMERG).
  • Probabilistic output uses public ensembles (GEFS/AIFS), not a proprietary calibrated model.
  • SQLite is single-writer — fine for a demo, not for concurrent operations.
  • Classified path, CDS, ATO, and 99.9% SLA are design-only locally.

Assumptions

  • Government furnishes CDS drop-point specs, formats & credentials and NIPRNet landing-zone details post-award.
  • Laptop has outbound internet to reach public data APIs during the demo.
  • Public data licenses permit prototype/demonstration use with attribution.
  • The demo audience accepts public-data analogs for proprietary capabilities.
  • Production will run in AWS (EC2 → GovCloud) as directed.

Risks & Mitigations

  • High — CDS latency/bandwidth to classified enclaves. Mitigate: compact GeoJSON payloads, delta updates, early spec exchange.
  • High — 14-day IOC / 30-day FOC schedule. Mitigate: phased delivery (Q&A #3), reuse this scaffold.
  • Med — Data source outages / rate limits / licensing. Mitigate: multi-source adapters, caching, cache-fallback.
  • Med — Model-bias fidelity for non-experts. Mitigate: explicit uncertainty UI, plain-language impact cards.
  • Med — ATO / RMF timeline. Mitigate: Government-sponsored ingestion (Q&A #4); prepare artifacts early.
  • Low — SQLite→PostgreSQL migration. Mitigate: SQLAlchemy/Alembic abstraction from day one.
